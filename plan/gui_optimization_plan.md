# GUI 优化与双账号测试计划

日期：2026-05-28

## 1. GUI 布局优化

### 1.1 当前问题

- 单账号标签页中，控制面板和推荐配方并排排列，窗口缩小时布局易变形
- 推荐配方区域占用了大量空间但信息密度低
- 整体窗口缺乏最小合理尺寸约束
- WeGame 配置区域虽然加了滚动条，但嵌套层次偏多

### 1.2 优化方向

- **控制面板精简**：将后台模式/调试模式/F8快捷键提示合并到更紧凑的布局，减少垂直占用
- **推荐配方区域压缩**：改用更紧凑的显示方式（如单行文本或更小的卡片），为主要日志区域腾出空间
- **窗口尺寸调整**：重新评估默认窗口尺寸（当前 880x780），确保各 tab 内容完整可见
- **WeGame 配置折叠**：考虑将各阶段默认折叠，用户按需展开，减少首次加载时的视觉复杂度

## 2. 日志区域修改

### 2.1 当前问题

- 日志区域高度偏小（`height=6`），多账号运行时日志快速滚动，大量历史信息不可见
- 单账号和多账号各自有独立的日志框，切换 tab 时日志不连续，排查问题不方便
- 日志没有持久化（关闭 GUI 后丢失），不便于事后分析

### 2.2 修改方案

- **增大日志区域**：调整 `grid_rowconfigure` 权重，让日志区域占据更多垂直空间
- **日志文件持久化**：将日志同时输出到 `./log/gui_{timestamp}.log` 文件，按日期切割
- **搜索/过滤功能**：在日志框上方添加简单的过滤输入框，支持关键字高亮
- **统一日志缓冲区**（可选）：考虑两个 tab 共用同一个日志缓冲区，切换时保持连续性

## 3. 双账号实际流程测试

### 3.1 测试环境

- 分辨率：1920×1080
- 账号：大号 + 小号（均 enabled）
- WeGame 模式：无边框窗口

### 3.2 测试步骤

1. 启动 GUI：`conda run -n deltaforce python gui/app.py`
2. 多账号标签页 → 点击"启动全部"
3. 观察完整流程：

| 步骤 | 预期 | 验证点 |
|------|------|--------|
| 大号 步骤 1-9 | 登录并导航到特勤处 | 日志显示每个步骤执行 |
| 大号 步骤 10 | dash_page 检测并启动制造 | 日志显示制造界面各部门状态 |
| 大号 步骤 11 | 退出游戏（alt+f4） | 游戏窗口关闭 |
| 大号 步骤 12-13 | 点击头像 → 切换用户 | WeGame 界面切换到账号选择 |
| 小号 步骤 1-9 | 自动登录并导航到特勤处 | 日志显示"=== 小号: 开始 ===" |
| 小号 步骤 10 | 启动制造 | 日志显示小号的制造状态 |
| 小号 步骤 11-13 | 退出+切换 | 完整收尾 |

### 3.3 风险点

- 步骤 6 固定等待 70s：若游戏加载超过 70s 会超时跳过
- 步骤 12-13 WeGame 窗口激活：可能因 WeGame 界面状态不同导致坐标偏移
- 制造启动时间不足：`craft_start_wait` 默认 70s 可能不够 dash_page 完成四个部门的检测，需关注日志中是否有 "制造启动" 的打印

## 发现问题

### 问题 1：步骤 6 等待时长不足

- **现状**：`wegame_switcher.wait_game_window(50)` 硬编码 50 秒超时
- **表现**：游戏加载（反作弊 + 登录验证）耗时超过 50 秒，导致超时跳过
- **修改方向**：改为 GUI 可配置等待时长

### 问题 2：各步骤等待时长不可配置

- **现状**：步骤等待时长全部硬编码（步骤 4 等待 6s、步骤 6 等待 50s、步骤 7 等待 10s）
- **问题**：不同电脑配置、网络环境需要的等待时间不同
- **修改方向**：在 WeGame 配置区为每个步骤添加等待时长输入框

### 问题 3：GUI 步骤顺序和布局需优化

- **现状**：仅按步骤序号排列，未按阶段分组，容易混淆
- **问题**：当前头像（步骤 12）和账号管理（步骤 1）位置接近，用户不易理解执行顺序
- **修改方向**：
  - 按阶段分组显示：登录阶段（1-3）、启动阶段（4-5）、导航阶段（6-9）、切换阶段（11-13）
  - 阶段间用分隔线或分组框区分
  - 步骤 10（自动制造）不参与坐标配置，可单独说明

## 修改方向

### 1. `wegame_switcher.py`

- `wait_game_window(timeout)`：将默认超时参数暴露给调用方
- 各等待时长改为从配置读取，而非硬编码

### 2. `gui/account_panel.py`

- 在 WeGame 配置区为以下步骤添加等待时长（秒）配置：
  - 步骤 4：点击三角洲应用前等待（默认 6）
  - 步骤 6：游戏加载等待（默认 80，原值 50 不足）
  - 步骤 7：跳动画前等待（默认 10）
- 按阶段重新组织 GUI 布局：
  ```
  ┌─ 登录阶段（步骤 1-3）──────────────┐
  │  步骤 1 账号管理: [坐标] [获取]      │
  │  步骤 2 点击账号:（列表中选择）      │
  │  步骤 3 登录按钮: [坐标] [获取]      │
  ├─ 启动阶段（步骤 4-5）──────────────┤
  │  步骤 4 三角洲应用: [坐标] [获取]    │
  │         等待: [6] 秒                │
  │  步骤 5 启动按钮: [坐标] [获取]      │
  ├─ 导航阶段（步骤 6-9）──────────────┤
  │  步骤 6 烽火地带: [坐标] [获取]      │
  │         游戏加载等待: [80] 秒        │
  │  步骤 7 按空格:（自动执行）          │
  │         跳动画前等待: [10] 秒        │
  │  步骤 8 按 Tab:（自动执行）          │
  │  步骤 9 特勤处入口: [坐标] [获取]    │
  ├─ 切换阶段（步骤 11-13）────────────┤
  │  步骤 11 退出方式: [alt_f4 ▼]      │
  │  步骤 12 当前头像: [坐标] [获取]    │
  │  步骤 13 切换用户: [坐标] [获取]    │
  └───────────────────────────────────┘
  ```
- 将`data/accounts.yaml`中的`wegame`段扩展为包含等待时长字段

### 3. `data/accounts.yaml`

```yaml
wegame:
  # 坐标配置
  switch_account_btn_pos: [1044, 580]
  login_btn_pos: [969, 705]
  game_app_pos: [204, 374]
  launch_btn_pos: [1517, 930]
  mode_btn_pos: [472, 482]
  dash_entry_pos: [844, 60]
  account_avatar_pos: [1044, 580]
  switch_user_btn_pos: [1200, 100]
  
  # 等待时长配置（秒）
  wait_before_app: 6        # 步骤 4：点击应用前等待
  wait_game_launch: 80      # 步骤 6：游戏加载等待
  wait_before_space: 10     # 步骤 7：跳动画前等待
  
  exit_method: alt_f4
  account_timeout: 600
```

# GUI 可视化界面设计方案

## 1. 概述

### 1.1 目标

为 Delta Force 自动化制造脚本提供可视化界面，替代纯控制台操作，使用户能直观地：
- 控制自动制造循环的启动和停止
- 查看每日推荐配方的获取内容和更新时间
- 实时监控四个制造台的运行状态
- 浏览运行日志

### 1.2 范围

本方案仅针对**单账号模式**的可视化界面，不涉及多账号管理功能。GUI 作为现有 CLI 模式的补充，两者可共存。

---

## 2. 技术选型

| 选项 | 选择 | 理由 |
|------|------|------|
| GUI 框架 | **tkinter** | Python 内置，零新依赖。界面需求简单（按钮、标签、文本框），tkinter 完全胜任 |
| 线程模型 | **threading.Thread** | 标准库，无需额外依赖。配合 `threading.Event` 实现可中断循环 |
| 日志机制 | **print 重定向** | 通过 `io.StringIO` 捕获 stdout，最小化代码侵入 |
| 配置读写 | **ruamel.yaml** | 与 `main.py` 保持一致，保留注释和格式 |

## 3. 架构设计

### 3.1 总体架构

```
┌─────────────────────────────────────────────────────────┐
│                    gui/app.py (入口)                      │
│                                                           │
│  ┌──────────────────────────────────────────────────┐   │
│  │             main_window.py (主窗口)                │   │
│  │                                                    │   │
│  │  ┌──────────┐  ┌──────────────┐  ┌────────────┐  │   │
│  │  │ 控制面板  │  │ 推荐配方展示  │  │ 部门状态   │  │   │
│  │  │ [启动]   │  │ 技术中心:XX  │  │ 空闲/制造中│  │   │
│  │  │ [停止]   │  │ 工作台:XX   │  │ 已完成    │  │   │
│  │  │ 状态灯   │  │ 制药台:XX   │  │ 剩余时间  │  │   │
│  │  └──────────┘  │ 防具台:XX   │  └────────────┘  │   │
│  │                 └──────────────┘                   │   │
│  │  ┌──────────────────────────────────────────────┐  │   │
│  │  │              运行日志面板                      │  │   │
│  │  └──────────────────────────────────────────────┘  │   │
│  └──────────────────────────────────────────────────┘   │
│                           │                              │
│                           ▼                              │
│  ┌──────────────────────────────────────────────────┐   │
│  │          main.py (自动化引擎，线程内运行)          │   │
│  │  - stop_event: threading.Event                    │   │
│  │  - status_callback: 部门状态 → GUI                │   │
│  └──────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 3.2 数据流

```
用户操作 ──→ GUI 按钮 ──→ 启动/停止 Automation Thread
                                        │
                    ┌───────────────────┴───────────────────┐
                    │              main() loop               │
                    │  每次迭代:                              │
                    │    1. 截图 → OCR → 检查部门状态         │
                    │    2. 调用 status_callback(状态)        │
                    │    3. sleep(remain_time) [可中断]       │
                    │    4. 检查 stop_event                  │
                    └───────────────────┬───────────────────┘
                                        │
                    ┌───────────────────▼───────────────────┐
                    │         GUI 更新 (通过 tk.after)       │
                    │  - 部门状态面板刷新                    │
                    │  - 日志面板追加文本                    │
                    │  - 状态灯/状态栏更新                   │
                    └───────────────────────────────────────┘
```

### 3.3 线程模型

- **主线程**: tkinter 事件循环（负责 GUI 绘制和用户交互）
- **工作线程**: 自动化循环（负责游戏交互、截图、OCR）
- **线程通信**:
  - `stop_event`（`threading.Event`）: 主线程通知工作线程停止
  - `status_queue`（`queue.Queue`）: 工作线程向主线程发送状态更新
  - `print` 重定向: 工作线程的输出被捕获并显示在日志面板

```
主线程 (tkinter)                   工作线程 (automation)
      │                                   │
      │  创建 stop_event                   │
      │  创建 status_queue                 │
      │                                   │
      │  用户点击 [启动]                    │
      │────── start() ──────────────────►  │
      │                                   │── main(stop_event, callback)
      │                                   │
      │                                   │── 循环开始
      │  每 100ms 轮询队列                  │
      │◄──── status_queue.put(状态) ───────│── OCR 检查部门
      │  更新 GUI                          │
      │                                   │── 暂停(可中断)
      │  用户点击 [停止]                    │
      │────── stop_event.set() ──────────► │── 循环退出
      │                                   │
      │  线程 join()                       │── 线程结束
```

### 4.2 控件说明

| 区域 | 控件类型 | 说明 |
|------|----------|------|
| 启动按钮 | `tk.Button` | 启动自动化循环，绿色背景 |
| 停止按钮 | `tk.Button` | 停止自动化循环，红色背景 |
| 状态指示灯 | `tk.Canvas` | 绿色圆点=运行中，红色=已停止 |
| 后台模式 | `tk.Checkbutton` | 绑定 `user_config['background_mode']` |
| 调试模式 | `tk.Checkbutton` | 绑定 `user_config['debug_mode']` |

## 5. main.py 修改设计

### 5.1 函数签名变更

```python
def main(stop_event: threading.Event = None, status_callback: callable = None):
```

### 5.2 修改点

| 位置 | 原代码 | 修改后 |
|------|--------|--------|
| main() 签名 | `def main():` | `def main(stop_event=None, status_callback=None):` |
| time.sleep | `time.sleep(remain_time)` | 可中断等待 |
| status_callback | 无 | 每次循环报告部门状态 |
| 异常处理 | 直接退出 | 通知 GUI 后退出 |

### 5.3 兼容性

CLI 模式调用 `main()` 不传参数，行为与修改前完全一致。

---

## 6. 错误处理

| 场景 | GUI 表现 |
|------|---------|
| 启动时 daily_fetcher 失败 | 推荐配方区域显示 "获取失败"，日志记录警告 |
| 游戏窗口未找到 | 日志显示错误，状态显示"等待游戏窗口..." |
| 分辨率不支持 | 弹出对话框提示 |
| 用户点击停止 | 立即中断当前 sleep，等待当前操作完成后结束 |
| 自动化线程异常崩溃 | 状态灯变红，日志显示错误信息 |
| 配置加载失败 | 启动时弹出错误对话框 |

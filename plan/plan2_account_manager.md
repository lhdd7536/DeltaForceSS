# 方案二：WeGame 多账号自动制造（固定位置点击方案）

## 目标

在现有单账号制造系统基础上，增加多账号支持，实现**一键启动、多账号轮流自动登录 WeGame 并执行特勤处制造**。

## 设计原则

- **固定位置点击**：WeGame 中已保存的账号通过固定坐标点击切换，不处理密码、不识别验证码
- **零新增依赖**：全部复用现有 tkinter + pyautogui + win32gui
- **最小修改**：不改动 `main.py`，新增模块独立于现有逻辑

## 数据存储

`data/accounts.yaml` — 仅保存账号名称和点击坐标，无密码：

```yaml
accounts:
  - name: "大号"
    click_pos: [962, 628]        # 步骤 2：账号按钮位置
    enabled: true
  - name: "小号"
    click_pos: [938, 665]
    enabled: false

wegame:
  switch_account_btn_pos: [60, 60]   # 步骤 1：切换账号按钮（可选）
  login_btn_pos: [960, 640]          # 步骤 3：登录按钮
  game_app_pos: [150, 400]           # 步骤 4：三角洲行动应用图标
  launch_btn_pos: [960, 800]         # 步骤 5：启动按钮
  mode_btn_pos: [300, 500]           # 步骤 6：烽火地带模式
  dash_entry_pos: [600, 350]         # 步骤 9：特勤处入口
  account_avatar_pos: [800, 400]     # 步骤 12：当前账号头像（可选）
  switch_user_btn_pos: [1200, 100]   # 步骤 13：切换用户按钮（可选）
  exit_method: "alt_f4"              # 退出方式
  account_timeout: 600               # 每账号制造时长（秒）
```

## 关键简化（相对原方案）

| 项目 | 原本方向 | 实际方案 |
|------|---------|---------|
| GUI 框架 | PyQt6 重写 | 沿用 tkinter，增加标签页 |
| 密码管理 | cryptography 加密存储 | **不保存密码** |
| 登录方式 | OCR + 密码输入 + 滑块验证 | **固定位置点击** |
| 进程管理 | psutil | win32gui.FindWindow |
| 新依赖 | PyQt6, cryptography, psutil | **零新增** |

## 单账号执行流程（13 步）

```
大号 ── 1.点击切换账号 ── 2.点击账号 ── 3.点击登录 ── 4.点击三角洲应用
      ── 5.点击启动 ── 6.点击烽火地带 ── 7.按 3 次空格 ── 8.按 Tab
      ── 9.点击特勤处 ── 10.自动制造 ── 11.ALT+F4 退出
      ── 12.点击当前账号头像 ── 13.点击切换用户

小号 ── 同上 13 步（复用链路）

[循环模式] → 回到大号
[单次模式] → 全部完成
```

详细步骤说明见 `plan/login_switching_flow.md`。

## 运行方式

```bash
conda run -n deltaforce python gui/app.py
# 在 GUI 中切换到"多账号"标签页使用
```
